In the previous section, we built the Flutter web front-end and completed the main VMS user experience. But right now, our application is still working with temporary data. It can show the screens, but it does not yet have a real back-end to process requests or a database to permanently store vehicle information. That is what we are going to build next. Our back-end will be a separate Java Spring Boot project. Flutter remains responsible for the user interface. Spring Boot will work behind the scenes, handling requests, applying the application's rules, and communicating with the database. SQL will provide permanent storage for our vehicle information. These are separate projects, but later we will connect them so they work together as one application. So what does the back-end actually do? Imagine a user registers a vehicle in Flutter. The back-end receives that request, checks the required rules, works with SQL to save the information, and then sends a result back. The same idea applies when we view, update, or delete vehicles. The front-end handles the interaction, while the back-end handles what needs to happen behind it. Just like the front-end, we will build the back-end in small steps. First, we create and run the Java Spring Boot project. Then, we connect the SQL database, build the vehicle logic, and create the REST APIs that Flutter will use later. By the end of this section, our back-end will be ready. In the next section, we will connect it to the Flutter front-end and replace the temporary data with real data.
