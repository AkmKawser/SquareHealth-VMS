We have built and tested our VMS locally, now it is time to make it available online. This is where CI-CD comes in. CI-CD gives us a structured way to move our application from development to a live environment. CI stands for Continuous Integration. In our project, this means reviewing our latest changes, committing them properly, and pushing them to GitHub. This gives us a reliable and trackable version of both our frontend and backend before deployment. CD stands for Continuous Deployment. Once our code is available in GitHub, deployment platforms can build and publish the application. Instead of keeping our VMS only on our computer, we make it accessible through a live URL. Our VMS has two separate projects. The Flutter web frontend will be deployed through Netlify, while the Java Spring Boot backend will be deployed through Render. They remain separate projects, but once connected, they work together as one live VMS. Before deploying anything, we need a clean and safe working state. The frontend and backend must remain separate, and we should review our changes before pushing them. Passwords, database credentials, API keys, and other secrets should never be committed to GitHub. That is our goal for this section. We will first push both projects to GitHub. Then, we will deploy the Flutter frontend to Netlify and the Spring Boot backend to Render. Finally, we will connect both sides and test the complete VMS as a real live application.
